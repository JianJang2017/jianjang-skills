## 为什么裁片图必须用代码算

生图模型画不了技术图纸，原因有两层：

1. **文本渲染不可靠**：扩散模型把文字当图案生成，数字会缺笔、错位、糊成一团。
2. **更根本的问题：数字是编的。** 模型标出的"袖长 20cm"和尺码表里的袖长没有任何计算关系，它只是画了一个"看起来像尺寸标注的东西"。打版师照着下剪，裁出来就是废料。

裁片几何本质上是确定性算术——给定人体尺寸和版型意图，每个点的坐标都能推导出来。这类东西属于该写进代码的：算一次，永远对，还能自动校验。

所以本技能的分工是：
- **效果图** → 执行环境内置图像生成工具（视觉表达）
- **裁片图** → `draw_pattern.py`（精确制图，代码擅长）

## 净样、毛样、缝份

三个概念不能混：

| 概念 | 含义 | 图上表示 |
|------|------|---------|
| **净样**（net） | 成衣尺寸，即缝合线位置 | 实线轮廓 |
| **缝份**（seam allowance） | 缝合需要预留的边量 | 净样与毛样之间 |
| **毛样**（cut） | 实际裁剪尺寸 = 净样 + 缝份 | 橙色虚线 |

尺码表和成本核算用的都是**净样**（成衣尺寸），但裁布要按**毛样**。少留缝份 = 衣服小一圈，这是新手最常犯的错。

本引擎的缝份默认值：

| 部位 | 缝份 | 为什么是这个值 |
|------|------|--------------|
| 肩缝 shoulder | 1.0cm | 直线短缝，1cm 足够 |
| 侧缝 side | 1.0cm | 同上 |
| 袖窿 armhole | 1.0cm | 曲线，留多了压不平 |
| 领口 neckline | 0.8cm | 曲率最大，缝份必须最小 |
| 下摆 hem | 2.5cm | 要折边（两折光边），需要量 |
| 袖口 sleeve_hem | 2.0cm | 同样折边，比下摆略少 |
| 腰缝 waist | 1.0cm | 直线拼接 |
| 裆缝 crotch | 1.0cm | 受力大但曲率也大，1cm 折中 |
| 对折线 fold | 0 | **对折边不加缝份**——加了就等于把衣服放大一倍缝份 |

对折线加缝份是个隐蔽错误，图上用蓝色长短点线明确标出"对折线"就是为了防这个。

## 放松量

`SIZE_CHART` 里存的是**人体净尺寸**，不是成衣尺寸。人体胸围 88cm 的衣服不能做成 88cm，得加放松量（ease），否则穿不进去也动不了。

```
成衣胸围 = 人体胸围 + 放松量
```

三档预设：

| 版型 | 胸围放松 | 腰围放松 | 臀围放松 | 适用 |
|------|---------|---------|---------|------|
| `fitted` 修身 | +6cm | +4cm | +4cm | 衬衫、连衣裙、正装 |
| `regular` 常规 | +10cm | +8cm | +8cm | 日常上衣、裤装（默认） |
| `loose` 宽松 | +16cm | +14cm | +12cm | 廓形衫、古风、外套 |

**针织面料折半**（`KNIT_EASE_FACTOR = 0.5`）：针织有弹性，按梭织的放松量做会松垮垮。T恤走的就是这条——`regular` 的 +10cm 实际只加 +5cm。

这也是为什么 T恤的 1/4 胸围是 23.2cm 而不是 24.5cm：`(88 + 10×0.5) / 4 = 23.25`。

## 上衣类计算公式

以 T恤/衬衫为例（`draft_tshirt`）：

```
1/4胸围     = (人体胸围 + 放松量) / 4        ← 半片前/后片的工作宽度
袖窿深      = 胸围 / 8 + 6.5                ← 比例分配法常用式
领宽        = 胸围 / 12 + 2.5
前领深      = 领宽 + 1.0                    ← 前领比后领深
后领深      = 2.0                           ← 固定浅量
肩斜        = 4.0cm                         ← 肩线下落量
袖山高      = 袖窿深 × 0.62                 ← T恤用浅袖山（宽松落肩感）
袖窿弧长    = 前片袖窿弧 + 后片袖窿弧        ← 对贝塞尔曲线数值积分实测，非比例估算
袖肥        ← 反解：使袖山弧长 = 袖窿弧长 + 吃势
```

**袖山高的取值逻辑**：合体装袖用袖窿深的 5/6（约 0.83），袖型立挺但活动受限；T恤用 0.62，袖子自然下垂、抬手舒服，代价是腋下有余量。这是款式选择，不是精度问题。

**袖山弧长必须匹配袖窿弧长**——这是装袖能不能装上的硬约束。

引擎的做法：先对前后片袖窿的二次贝塞尔曲线做数值积分，得到实际弧长；再用二分法反解袖肥，使袖山弧长正好等于「袖窿弧长 + 目标吃势」。所以袖肥是解出来的，不是套公式估的。

| 款式 | 目标关系 | 原因 |
|---|---|---|
| T恤装袖 | 袖山 = 袖窿 + 1.5cm | 常规吃势，袖头微饱满 |
| 古风宽袖 | 袖山 = 袖窿 + 2.0cm | 廓形宽松，袖头更饱满 |
| 泡泡袖 | 袖山 = 袖窿 × 1.18 | 抽褶量按比例，不是固定差值 |

图纸上每条弧线都标了实测弧长和凹势（曲线偏离弦线的最大垂距）。只给端点坐标的图纸是不可复现的——同样两个端点、不同凹势，缝出来的袖窿周长不一样。凹势是打版师用曲线尺放样时真正要对的那个数。

## 下装类计算公式

```
立裆深      = (臀围 + 放松) / 4 + 2
前臀宽      = (臀围 + 放松) / 4 - 1          ← 前片窄 1cm
后臀宽      = (臀围 + 放松) / 4 + 1          ← 后片宽 1cm，需包臀
前腰宽      = (腰围 + 放松) / 4 - 1
后腰宽      = (腰围 + 放松) / 4 + 1
前裆宽      = (臀围 + 放松) / 20
后裆宽      = (臀围 + 放松) / 10             ← 后裆宽是前裆的两倍
膝位        = 立裆深 + 下裆长 × 0.48
后腰起翘    = 1.5cm                          ← 贴合坐姿
```

**前后片为什么不对称**：人体前面平、后面凸（臀部），所以后片要宽、后裆要深、后腰要起翘。把前后片裁成一样的，成品会前面堆布、后面绷紧、坐下时后腰往下掉。

**横裆宽 ≠ 臀宽**：横裆线在裆底，包含裆宽延伸量；臀围线在其上方。这两个尺寸差 5cm 以上，混淆会导致打版师找错基准线。（这是开发中真实出现过的标注错误，现已加入自动校验。）

**周长校验**：`(前臀宽 + 后臀宽) × 2 = 臀围 + 放松量`。左右两条腿各一片前、一片后，所以是 ×2。测试里就是按这个式子验的。

## 连衣裙计算公式

按腰缝断开（分割式）起版，这是连衣裙最常见的结构——上身贴合躯干，裙摆独立放摆。

```
腰节长      = 衣长 × 0.40                    ← 腰线位置占总长四成
裙长        = 衣长 - 腰节长
腰省收量    = (胸围 - 腰围) / 8              ← 胸腰差的八分之一
V领深       = 领宽 + 6.0
下摆放量    = 每片 +8cm                      ← A 字廓形
泡泡袖袖山  = 袖窿深 × 0.72
抽褶量      = 袖窿弧长 × 1.18                ← 抽褶前的弧长
```

**泡泡袖的抽褶量**：袖山弧长做成袖窿的 1.18 倍，多出来的 18% 抽褶塞进袖窿，形成蓬起效果。倍数越大越蓬，1.3 以上会很夸张。

## 交领上衣的特殊结构

古风交领（`draft_crossover_blouse`）与 T恤最大的区别：**左右前襟不对称，不能互为镜像**。

```
搭门量      = 胸围 / 12                      ← 大襟越过前中线的量
大襟宽      = 1/4胸围 + 搭门量               ← 压在上层
小襟宽      = 1/4胸围 - 搭门量 × 0.4         ← 搭在下层，更窄
袖窿深      = 胸围 / 8 + 7.5                 ← 比现代款更深（宽松廓形）
肩斜        = 3.2cm                          ← 平肩
落肩量      = +1.5cm
下摆开叉    = 衣长 × 0.28
```

**把两片前襟裁成一样是这个款式的典型错误**。大襟要覆盖到右腋下，小襟只需搭到中线附近。裁成一样宽，交领交不上，或者门襟堆叠过厚。

引擎里这两片是独立的 `Piece`，宽度不同，测试里有一条专门断言 `大襟宽 > 小襟宽`。

## 标注自校验机制

每个 `Dim`（尺寸标注）同时携带两样东西：

1. **几何位置**：`p1` 到 `p2` 两个坐标点
2. **标注文本**：形如 `"袖长 20"`，数值写在 label 里

`validate_pieces()` 做的事：把 label 末尾的数字抽出来，和 `p1`→`p2` 的实际距离比对，差值超过 0.15cm 就报错。

```python
problems = validate_pieces(pieces)
if problems:
    raise SystemExit(1)   # 拒绝出图
```

**为什么值得做这道检查**：一张标注与几何矛盾的图纸比没有图纸更危险——它看起来权威，打版师会照着做。开发过程中这道检查抓到两个真实 bug：

- 袖长标注的线段起点写在了腋下点（而非袖山顶），标注写 20 实测 9.2
- 横裆宽被误标成臀宽，数值差 5.1cm

两个都是肉眼看图很难发现、但会直接导致裁错的错误。

`draw_pattern.py` 在渲染前必跑这道检查，不通过就退出，绝不输出一张自相矛盾的图。

## 扩展新款式

加一个款式需要三步：

**1. 写 drafter 函数**，返回 `List[Piece]`：

```python
def draft_skirt(m: Dict[str, float], fit: str = "regular") -> List[Piece]:
    waist, hip = m["waist"], m["hip"]
    e = EASE[fit]
    waist_q = (waist + e["waist"]) / 4
    hip_q = (hip + e["hip"]) / 4

    front = Piece(
        name="前片", name_en="Front", qty=1,
        fold_edge="left", grain="vertical",
        seams={"waist": 1.0, "side": 1.0, "hem": 2.5},
        note="连折裁",
        path=[("M", 0, 0), ("L", waist_q, 0), ...],
    )
    front.dims = [
        Dim("h", (0, 0), (waist_q, 0), f"1/4腰围 {waist_q:.1f}", offset=-2.5),
        # label 里必须写进数值，否则无法校验
    ]
    return [front, ...]
```

**2. 注册进 `DRAFTERS`**：

```python
DRAFTERS = {
    ...
    "skirt": ("bottoms", draft_skirt),
}
```

**3. 跑测试**：`python3 tests/test_pattern_drafting.py` 会自动把新款式纳入全尺码校验。

写 `Dim` 时的注意点：

- **label 必须包含数值**，格式 `"名称 数值"`，校验器抽取末尾数字
- **`kind="h"` 量水平距离，`"v"` 量垂直距离**，别搞反
- **`offset` 正数向下/右，负数向上/左**，用来避免标注线互相压叠
- 如果某个尺寸不对应图上任何一条线段（比如从公式直接得出的周长），传 `value=` 显式指定，校验器会跳过几何比对

## 这套引擎的局限

必须如实告诉用户的部分：

1. **这是 1:N 示意图，不是可裁剪纸样。** 图上尺寸准确，但要落地必须由打版师出 1:1 实样。本引擎不导出 DXF/PLT，也没有做纸样的曲线顺滑处理。

2. **曲线是二次贝塞尔近似。** 真实打版的袖窿、裆弧要用曲线板逐点调顺，本引擎用一段 Q 曲线近似，形状对但不够顺。这影响成衣的合体度，不影响尺寸核对。

3. **没有省道展开。** 连衣裙的腰省只给了收量数值，没有在图上画出省道的三角形形状和省尖位置。复杂的胸省转移、公主线分割都不支持。

4. **吃势的分配位置未表达。** 两条弧长已实测吻合（见上文袖山反解），但吃势该集中在袖山头、腋下不吃，属缝制工艺，图上只给总量。

5. **不含工艺细节。** 扣位、袋位、明线位置、粘衬范围都没有标注。

6. **毛样线是缩放近似，不是真正的等距外扩。** 图上橙色虚线用于表达"裁剪线在缝合线之外"，各边的精确缝份值以文字表格为准，不要用尺子量图。

7. **只覆盖基础廓形。** 插肩袖、连身袖、垫肩结构、多片分割、斜裁都未实现。

前六条都是"图能用于沟通和核对，但不能直接进裁床"的具体表现。跟用户交付时把这句说清楚，比让他们自己撞上去要好。
